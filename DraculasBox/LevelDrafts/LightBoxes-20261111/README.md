# 灯与箱子：关卡试作

五关供自定义关卡库审核，尚未替换正式主线。沿用现有规则，没有新增机关。

先玩关卡，再看下方解法。01、02 是短谜题；03、04 增加搬运和站位规划；05 组合前面的操作。

| 自定义库名称 | 这关在问什么 |
| --- | --- |
| 试作 01 · 回灯 | 为了抵达灯的另一侧，能不能先改变通路，再恢复它？ |
| 试作 02 · 顶替 | 正在挡光的箱子也挡住了出口，如何把它挪开？ |
| 试作 03 · 绕送 | 人能绕墙走，箱子不能拉，如何把箱子送到灯的另一面？ |
| 试作 04 · 借位 | 目标附近的操作格被另一盏灯照着，先处理哪一个问题？ |
| 试作 05 · 并灯 | 搬灯用过的箱子能否收回，并用于推动两盏灯？ |

## 对现有关卡的判断

- 第一章“照射”最短只需沿同一方向把灯推两次；“归途”也只需向下搬灯。适合初次示范，连续放在章节尾部缺少变化。
- 第二章“借过”的 B 箱可以完全不动；“交叉”只需分别摆好两箱。它们验证了规则，但作为连续的主线挑战，核心决策相近。
- “回身”已经有换向和复用，不应因为整改而一并推翻。先用试作比较体验，再决定替换哪些关卡及放置顺序。

`campaign-audit.json` 是当前关卡按真实 Core 规则搜索的结果。最短步数、搜索量都不能证明玩家会觉得有趣。

### 01 回灯

下方箱子把灯向上推一格，打开左侧绕行路线，同时照亮了右侧棺材通路。玩家从左侧绕到上方，挪开挡住站位的箱子，再隔着上方箱子把灯推回原位。现在人处于上半区，能进入棺材。

重点是同一个灯位往返对应两次不同的通行需求。继续上推灯无法通关；出口下方的墙封住了绕过光路的捷径。三次推动，13 步；三只箱子均有作用。

### 02 顶替

A 起初挡住横光，也堵住上下区之间的入口。先右推 A 腾出下区通道；走到 B 下方，将 B 推进同一条光路，接替 A 的遮挡。此时才能安全移开 A，进入其右侧的棺材。A 向上或向下移开都是有效解。

重点是挡光与占路发生在同一个实体上，B 不是另一条独立光路的停车位。删去第二盏灯与透光缺口，使交接更容易读懂。三次推动，16 步。

### 03 绕送

上排的两箱需要连推，才能把待运输的箱子送至左侧转弯处；玩家再绕上方墙体，向下送箱，最后从箱子的左侧推它去挪灯。也存在改用另一只箱子完成搬运的等价解。

重点是人的绕路和箱子的运输路线不同，箱子必须换方向、换操作面。禁止连推时无解。六次推动，17 步。

### 04 借位

要把左灯向左推，必须站在其右侧的操作格；但这个格子被右灯照亮。先用 B 将右灯下移，才能安全把 A 运到左灯旁，完成横向推动。右灯的处理是在创造操作空间，而不是直接替出口挡光。

两灯与两箱均必须移动。六次推动，17 步。

### 05 并灯

A 护送上方灯向右进入 B 下方，由 B 接手将灯向下搬至另一盏灯所在的一排。上排光路消失后，A 才能被收回、转送到下排，最后隔箱推动两灯组成的队列，腾出棺材入口。

两灯同时被推不是演示花样：禁止双灯同推时无解。十六次推动，28 步。它刻意保留为最后的组合挑战，但来回运 A 是否拖沓，需要实际试玩判断；不把较长解法直接等同于较高品质。

## 验证边界

- `analysis.json`：链接项目真实 Core 的最短解、逐步推动记录、逐物件冻结测试。
- `proofs.json`：针对核心构思的限定搜索。只有搜索穷尽才记录为无解，达到预算不作此结论。
- `Play/report.json`：Unity 后台隔离档案中的自定义库读写、原生编辑器打开、试玩按钮与 F5 共享分发入口、逐步输入、撤销重置、通关返回，以及选定死亡声的实际引用检查。
- `publication.json`：向玩家实际自定义库写入的记录。正式关卡、已有自定义关卡和玩家进度不在修改范围。

这些是可解性与流程验证；五关的乐趣、难度及最终编排仍待用户审核。

本轮验证结果：Unity 后台隔离试玩 5/5 通关，159 项检查通过。8 项核心动作限定搜索均穷尽无解。正式关卡文件与原有玩家档案文件的哈希保持不变。
