# SokobanGame 设计基准

> 日期：2026-11-06
> 定位：记录原型的高层设计依据；当前仅建立工程事实基线，玩法设计待所有者确认。

## 1. 原型目标与验证标准

项目工作名为 `SokobanGame`，对应仓库为 `26H4_SokobanGame`。正式原创项目的具体玩法仍待确认；当前已授权的独立研究任务是复刻《Box or Void》前两章，并实现面向玩家的游戏内关卡编辑器。研究目标、机制和实机证据集中在 [研究模块](../../Studies/BoxOrVoid/README.md)，不据此冻结后续原创项目设计。

正式开发前需明确：原型要回答的核心问题、玩家可感知的成功条件、实际运行环境，以及由所有者验收的体验标准。当前没有已确认的玩法、美术或性能验收结论。

## 2. 核心玩法循环

待所有者确认。暂不规定移动、推动、胜负、撤销、关卡或进程规则；这些内容有真实需求后进入对应系统策划案，本节只维护高层循环。

## 3. 美学规范

视角、美术方向、受限色板与 UI 视觉层级尚未确定。模板携带的场景与渲染资源不代表已选定的项目美术方案。

色板确定后在本节记录颜色与用途，由统一资源或配置承载引用；不在设计未定时填入示例色值。

## 4. 技术选型基线

以下为本地工程文件已声明或可直接查见的继承基线，不代表兼容性、编译或运行验收通过。

| 项 | 当前证据 |
|---|---|
| 引擎与语言 | `ProjectSettings/ProjectVersion.txt` 声明 Unity `6000.3.6f1`；工程使用 C# |
| 渲染 | `Packages/manifest.json` 声明 URP `12.1.15`；`ProjectSettings/GraphicsSettings.asset` 配置了渲染管线资源引用 |
| 异步 | manifest 通过本地包引用 UniTask |
| 文本 | manifest 声明 TextMeshPro `3.0.6` |
| 继承工具与框架 | 工程带有 CakePac、Aya.Events、DOTween、Odin Inspector、MK Toon 等既有代码与资源 |
| 场景入口 | `ProjectSettings/EditorBuildSettings.asset` 将 `Assets/Scenes/Gameplay.unity` 列为启用场景 |

包版本与引擎版本的兼容性尚未核验；文档初始化不调整依赖。目标平台、输入方案与发布规格待确认。后续变更以工程配置为证据，理由进入决策日志，跨模块约定进入技术框架。

## 5. 里程碑与验收

路线和进度以[版本开发文档](../版本开发文档.md)为准，当前不预设里程碑编号。

首个玩法版本立项前，应先确定核心验证问题与可判定的体验验收标准；功能验收应覆盖实际运行的完整玩法流程。构建、测试或静态检查结果不能替代体验验收。
