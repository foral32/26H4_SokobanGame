# Dracula’s Box 设计基准

> 最近更新：2026-11-11。项目英文名暂定 Dracula’s Box；文件与模块标识建议为 `DraculasBox`。

## 1 项目定位

Dracula’s Box 是一款二维格子推箱解谜游戏。玩家操控会被太阳光和危险点光伤害的小吸血鬼，推动箱子改变遮蔽与路线，最终进入棺材。采用固定正交俯视、四向走推和离散动作，操作反馈以轻巧的 Juicy 动效为主。

吸血鬼题材直接承担规则传达：角色需要躲避太阳光与四向点光，实体能改变受光区域，棺材提供封闭庇护。深度来自可达路线、施力位置与光影遮蔽之间的约束；两类光源的传播与遮挡规则不同，需分别呈现和计算。

## 2 核心机制概览

| 要素 | 当前设计 |
|---|---|
| 吸血鬼 | 四向走动或推动，一次一格；踏入危险光后死亡，可撤销恢复 |
| 普通箱 | 一格刚性实体，能推不能拉；首版没有高箱或高度分支 |
| 太阳光 | 按关卡配置开关与来源方向；普通箱在背光侧投两格影 |
| 四向点光 | 同关可放置多盏，可推动；各自向上下左右出光，遇遮挡停止、遇斜镜反射 |
| 斜镜 | 可推动，固定为 `/` 或 `\` 朝向；四向灯光碰到镜面转向九十度，两面均反射，支持连续反射 |
| 压力板 | 角色、箱子或灯持续占据时触发；同组任意一块被压下，该组门即开启 |
| 自动门 | 固定在地板上；关闭时挡路、挡光，开启时允许通过；门格有角色或物体时等待清空再关闭 |
| 安全判定 | 任一危险光源照到的普通地板均不安全；夜晚关闭太阳，点光仍然危险 |
| 墙与地板 | 墙固定挡路、挡光；地板亮暗变化，不改变其地形身份 |
| 棺材 | 固定终点，角色进入且该格未受光才通关；箱子无需归位 |
| 试错 | 提供撤销和重置，保留完整局面恢复能力 |

太阳光按关卡配置的方向传播，普通箱在背光侧形成两格影；首版墙体与普通箱同高，也投两格影。每盏四向点光沿四条轴线传播，遇墙、箱子、另一盏灯或关闭的门即停止该方向的射线。各光源分别计算后合并危险格：挡住一束光，不会消除另一束仍照到该格的光。前期太阳开关与方向为关卡参数，后期可由场内组件改变日照或时段。

走推先计划整条相邻实体链；空间可通行就提交整步，再按新布局判断落点受光。角色可踏入光内并死亡，这一步的位移和推动都计入历史；死亡后停止走动，播放灼烧、散灰、音效与画面反馈，再提示「Z 撤销」。棺材格也参与受光判定，只有落点不受任何危险光照时才能入棺通关；受光时走入仍会死亡。箱子与灯不能被推到棺材上。撤销恢复完整局面，包括死亡步推动的物体；重置本身也可撤销。

机关使用持续承重，不采用计时或踩一次切换。每步按开始时的门状态判断通路，提交位移后依次更新压力板、门和光照，再判断生存；开门放进光线也可能致死。关门对太阳投两格影，对点灯停止射线，沿用墙体的遮挡规则。门格被占用时保持开启，物体自身仍然挡光。连接组用相同颜色及点数对应，最多四组；不要求玩家阅读电路逻辑说明。

镜子沿用实体链推动、承重和完整撤销，不增加旋转指令。四向灯光到镜面后停止直行，只沿反射方向继续传播；箱子、其他灯、墙与关闭的门仍会挡住反射光。来自不同方向或不同光源的反射叠加。镜子自身不发光，光路随完整新布局重新计算。第四章以夜间关卡展开；编辑器中的镜子继续按同高实体投两格太阳影，太阳反射尚未扩展。

## 3 核心循环

观察日照、点光射线、箱影与棺材 → 找到安全推位 → 走动或推动箱子与点光灯 → 按新布局重算危险格 → 继续规划或撤销 → 入棺通关。

移动物体会同时改变通行与光照。规则层先形成完整的新局面，再判断角色是否安全，避免物体已移走却仍沿用旧影。

## 4 视觉与动效方向

沿用现有项目的简洁几何风格：浅色方块角色和箱子、灰蓝墙体、浅蓝高光与灰紫暗边；地板保持平面。角色的小披风与尖牙、棺盖的月牙共同传达吸血鬼题材。

灯具采用已选回的第一版造型：灰蓝方底座、中央圆灯芯、四向短出光口，明确表现四条危险光轴。金环星形灯及后续四个替代造型不作为当前美术选择。

地板使用同一石材纹理与轻量格缝，受光区域统一提亮为中性浅色，阴影保持冷灰蓝；光照不生成独立的黄色地块或每格重复的亮带。场外只保留一组清晰的太阳与方向标记，迎光棱面及背光侧投影共同表达来光方向。光影随实体位移过渡，视觉变化不扩展规则计算出的危险格。角色保留完整白色方脸、小披风与小獠牙，脸内不增加服饰图案。

行走和推动主要使用位移、挤压回弹与披风滞后；普通箱保持刚性。入棺使用角色缩小下沉、入口遮罩和独立棺盖滑合，不以逐帧肢体动作作为主要方案。具体参数留到实机调试。

主界面、章节、选关与暂停界面参照 Box or Void 的信息层级和交互反馈组织：大字号立体标题、几何图标入口、低对比漂移轮廓背景、编号关卡块、锁与完成标记、明确的焦点角标。“暮夜”主题以深蓝灰 `#202530` 为底，暖白 `#F2EFEB` 承担主文字，灰紫 `#7B4C62` 承担标题厚度，浅金 `#EDCA8F` 承担焦点与完成反馈。编辑器与关卡库采用浅灰界面、深蓝灰棋盘、灰紫选中态与浅金试玩入口；素材栏可滚动和收起，场景属性按需展开，绘制／擦除与点涂／矩形分别选择；标题使用现有粗黑体，说明使用现有思源黑体。

主菜单采用已选定的中轴构图：独立切角字标分为 Dracula's 与 BOX 两行，O 由带小披风、獠牙的吸血鬼方块替代，保留明确行距；下方为竖排文字菜单，开始游戏略大于其余入口。字标素材按当前主题映射正面色与厚度色，菜单使用原生文本承担导航、悬停与点击反馈，删除原有示意条和圆形入口。Unity Play 模式右下角「编辑正式关卡」继续独立锚定并保留功能。

主题提供暮夜、酒红、钴蓝、月蚀、瓷蓝五套配色，酒红为新进度默认主题；月蚀和瓷蓝采用已认可的上一版，不使用后续精修配色。设置只显示一行「主题」和当前名称，方向键左右或点击两侧箭头循环切换，即时生效并保存；菜单、棋盘、关卡库和编辑器共同应用。红色支线边框和机关组颜色保留功能含义。

通关完成入棺与棺盖闭合后，以圆形转场进入本章下一主线关；首次完成本章全部主线时，返回本章选关，已完成节点依次回弹并散出少量粒子，结束后显示「下一章」入口。未完成支线不参与攻克反馈；重玩章末关、完成支线或完成最终章均停留在本章选关。试玩通关直接返回编辑原稿。不显示额外的下一关面板。暂停与设置采用淡入，鼠标和键盘共用焦点，返回时保留选择；音量和编辑属性原位更新。

关卡编辑器在工具与素材旁标注快捷键：A 选择、Q 绘制、E 擦除；P 点选／点涂、R 框选／矩形，数字选择素材，两种斜镜改用 [／]。选择模式单击优先选中物件，框选包含区域内的地形、物件和机关；拖动预览、松手提交，Delete 删除选区，Esc 取消。一次移动或删除占一次撤销，越界或目标被占用时保留原稿。保存、试玩、撤销与重做也显示对应按键；输入文字时不触发工具。素材使用「玩家」「缺口」命名，连续缺口只绘制外围深坑边缘。编辑器提供直接输入的 3–32 格尺寸、独立日照方向、取色、滚轮缩放、中键平移、分组历史及光照预览。关卡库单击选择、双击或 Enter 编辑，悬停不改变文件操作目标。

正式关卡图悬停节点时按住空格，在就近小窗预览当前草稿及光照；松开空格、移出节点或开始拖动即关闭，预览不写入草稿。单击节点直接编辑，「…」与右键菜单只保留复制关卡、移至章节、删除关卡；后两项使用原关卡图上的紧凑弹窗。顺序与主支线通过拖动调整，目标槽预览、松手提交、取消不修改目录。关卡显示名称由当前位置生成「1-1 箱子」「2-5A …」前缀；编辑标题时编号单独显示，不写入名称或改动稳定 ID。正式关卡入口仅在 Unity 编辑器主菜单右下角显示。 章节关卡图提供「导入自定义」：分页选择已保存的自定义关卡，预览后「加入本章」，作为独立主线草稿插入选中节点后；之后可拖动排序和调整主支线。取消不创建关卡，导入不修改源自定义关卡。

写回工程按编辑条目勾选，默认全选；改名、棋盘、解法、新增关卡及编排可分开选择。未通过校验的条目显示具体原因，点击写回仍提供原因反馈；可取消勾选问题项，先写入其余修改。新章节与所属关卡、支线与所属主线保留必要依赖。有效路线的派生推数自动校正；未勾选的内容保留在草稿中，写入或草稿保存失败保留原工程与工作内容。

预览小窗以棋盘为主体，标题居中放在下方，使用圆角、柔和投影与短暂浮现。关卡库的「复制正式关卡」先按章节展示实际缩略图，主线与支线均可选择，确认后生成独立副本并进入编辑；取消不创建文件。

主菜单设置依次提供「清除关卡进度」「解锁所有关卡」，两项均需持续按住 1.4 秒；名称保持不变，文字逐渐放大，并伴随逐渐增强的轻微颤动，不显示进度圆圈。只让文本子节点运动，保持鼠标命中区域稳定；松手、移出或失焦即取消并迅速复原。成功时文字弹回，粒子围绕整段文字散出，约半秒收束：清除为下落细屑，解锁为向外散开的亮点。失败原位显示「写入失败」后恢复名称，保留原进度并允许重试，不播放成功动效，不新增弹窗。解锁开放全部章节、主线与支线，不改变真实通关记录；清除重置通关、解锁与续玩位置，保留自制关卡、编辑草稿、主题和音量。游戏暂停中的设置不显示这两个入口。

「关卡解」以玩家成功移动一格为一步，连推多个物件也算一步。求解完成后显示最短步数和推动次数。达到预算时可以扩大搜索，只有穷尽可达局面或地形隔断时才显示无解。回放支持暂停、前后单步和重播。手动试玩通关也能留下路线，每关保留较短的一条。改名保留解，改变布局或日照后重新求解，撤销可取回原解。

「草稿预设」提供独立设计的紧凑房间，可从关卡库新建，也可预览后替换当前棋盘。可用机制是筛选上限，不要求每稿使用全部选项；斜镜同时启用四向灯。当前 15 稿覆盖推箱、接影、移灯、承重开门及转光，保留绕行、换侧和回收物件的空间，不再串联狭长房间。难度用罗马数字展示，当前素材为Ⅰ至Ⅲ的设计者暂定分组，不据步数自动评级；没有相应素材的档位不可选，切换机制时选取最近可用档。预览只显示名称与难度；换稿优先更换同档的独立谜题，仅有一稿时明确显示。采用后可自由绘制，替换保留原身份与名称，并占一次撤销。

导入、导出、关卡移除、未保存退出与操作失败均使用覆盖原界面的紧凑弹窗。导入先选择或粘贴 JSON 路径，在同窗预览后确认；改变路径立即使旧预览失效。导出显示关卡名称和实际文件路径，提供打开文件夹与复制路径。关闭弹窗回到原编辑或关卡库上下文。

未保存标记比较完整内容与磁盘版本，撤销回到已保存内容会清除标记，恢复的未保存草稿仍需保存。明确放弃的草稿不再恢复；保存或导出失败应给出可见反馈并保留当前原稿，移除可跨会话恢复，冲突不覆盖已有文件。草稿与试玩入口统一检查结构，允许尚未放置角色或棺材的草稿继续编辑，拒绝可能破坏预览的重叠与越界数据。品质判断核对实际画面、连续操作、异常输入、文件占用及窗口适配。

界面遵循 less is more：只保留必要名称、操作按钮和错误提示；删除标语、常驻教学、重复状态、底部操作说明，以及面向玩家的实现解释。规则通过关卡与视觉反馈传达。

## 5 技术基线与范围

| 项目 | 当前工程依据 |
|---|---|
| 引擎与语言 | `ProjectSettings/ProjectVersion.txt` 声明 Unity `2022.3.51f1`，使用 C# |
| 渲染与文本 | 当前 `Packages/packages-lock.json` 解析 URP `14.0.11`（内置包按编辑器版本生效）、TextMeshPro `3.0.6` |
| 可评估复用 | 现有输入、动效编排、UI、转场、关卡数据与编辑工具结构 |
| 正式模块 | `Assets/DraculasBox/`，基础职责见[技术框架](../技术框架.md) |

当前正式目录为四章共二十四个主线、六个可选支线及关卡编辑器，Windows 键鼠操作，每章六个主线；第二、三、四章各有两个支线。第一章以走推、箱影、转身位置与四向灯为教学脉络。第二章「阳灯」引入交叉光线、错开灯位与遮挡物回用；第三章「通行」探索持续承重、关门遮光、门内挡光箱与两组机关的往返配合。第四章「镜面」从单镜转光、借墙消除反射，展开至连续反射、多灯换位和镜子承重。支线侧重物件接替和往返取回，较早教学关不放在章末充数。章节长度以不同解题内容为准。

连续操作保留短暂的单步输入缓冲；短按与长按重复区分，撤销、重置和离开页面会清除待执行方向，避免历史操作之后额外移动。

游戏按章节组织；完成一章全部主线即可过章。完成指定主线节点解锁对应支线；支线放在主线下方，锁定、解锁及完成后均保留红色外框。支线不计入主线完成数，不阻挡后续主线与章节解锁。旧存档已解锁的章节和已完成关卡的重玩入口保留。感光板、时段切换机关与高箱尚未实施。文档保持基础设计与架构范围，不另建具体关卡案和验收文档。

[Box or Void 研究模块](../../Studies/BoxOrVoid/README.md) 保持独立，其素材、关卡与完成记录不自动归属于原创项目。项目状态见[版本路线](../版本开发文档.md)，取舍见[决策日志](../DECISIONS.md)。
