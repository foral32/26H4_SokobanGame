# 游戏内关卡编辑器：需求与交互提案

2026-11-06 · **待所有者审核，尚未开始 Unity 编辑器功能实现。**

配套：[可交互界面稿](editor-review.html)。网页是可点击的设计样机；绘制、叠层选择、撤销重做、检查和试跑返回用于说明交互，不代表 Unity 功能已交付，也不承担正式数据保存。顶部有设计稿导航，正式游戏不保留这一条。

## 1. 当前工具与目标差距

当前 `Tools > Box or Void Study > Level data workbench` 是 Unity EditorWindow：载入已有 JSON、点选格子、添加/删除层、撤销、结构检查、另存副本，以及向已运行的共享场景送入数据。它不在游戏内；缺少新建流程、绘制工具、重做、选区批量操作、草稿管理、尺寸调整、自动恢复及试跑返回。这是研究数据辅助工具，不是完整关卡编辑器。

本轮设计目标：LD 在打包后的游戏里，不接触 Unity 或 JSON，即可从空白/模板建立关卡，清楚地处理黑白叠层，试跑验证想法，返回继续修改，最后保存并导出一个可重新载入的关卡文件。沿用前两章机制，不增加蛇、黏性等后续章节对象。

## 2. 建议的产品形态

| 方案 | 优点 | 代价与判断 |
|---|---|---|
| 全屏棋盘 + 临时浮动工具盘 | 最接近游玩画面 | 工具和层次经常被遮住，持续编辑的发现成本高 |
| **中央棋盘 + 左工具 + 右属性/层次** | 绘制、核查叠层、反复试跑都有稳定位置；适合桌面 TD/LD 工作流 | 占用一定横向空间；建议采用，窄窗口可折叠两侧 |
| 在 Unity 内扩展当前窗口 | 可复用 Editor API | 无法满足打包后游戏内编辑的要求，不作为交付方案 |

方案尚未获批。设计稿采用第二种布局供审核。

入口：主菜单增加有文字的「关卡编辑器」入口，进入「我的关卡」；原有剧情章节进度与自制关卡分开。不要把编辑器藏在设置页或只靠一个无标注图标进入。

视觉：继承原作蓝灰底、黑白棋子、方形边框、绿色四角选框和轻微投影。工具区保持克制，中央棋盘是视觉主角。正文用清晰中文无衬线字体；标题沿用较厚字重；不在编辑区堆叠原作展示性大字。颜色不能单独承担“选中、报错、完成”等含义，配合轮廓、符号和文字。

建议视觉 token：底色 `#30383D`、面板 `#252D32`、分隔 `#47565E`、正文 `#E8EDF0`、次要文字 `#A9B7BF`、选择 `#86C84A`、问题 `#E8AD67`。这些是设计提议，不宣称与原作逐像素一致。

## 3. 页面与主要操作

| 页面 | 主要任务 | 核心控件与反馈 |
|---|---|---|
| 我的关卡 | 新建、继续、管理与分享 | 棋盘缩略图、名称、尺寸、更新时间、草稿/结构有误/已试通状态；搜索、排序、新建、导入；卡片菜单内放复制、重命名、导出、删除 |
| 新建关卡 | 确定起点 | 名称、尺寸、表现主题「欢迎 / 箱即是空」、空白或内置关卡副本；提供小棋盘预览，默认 9×7 |
| 编辑 | 绘制并理解当前布局 | 顶栏名称与未保存状态、撤销/重做、检查、保存、试跑；左侧工具/对象/颜色；中央棋盘；右侧选格层次与关卡属性 |
| 问题检查 | 找到需要修复的位置 | 错误与建议分组；显示原因、坐标、处理建议；点选定位对应格子；结构通过与可解性分开表述 |
| 试跑 | 验证玩法 | 完整复用当前游戏规则、反馈和快捷键；顶部常驻「试跑中」与「返回编辑」；不改原始草稿、不计剧情进度 |
| 调整尺寸 | 改边界而不误裁布局 | 宽高、九宫格锚点、裁切预览、受影响对象数；裁切需明确确认，整个操作可一次撤销 |
| 离开/恢复 | 保护编辑成果 | 未保存时保存/放弃/取消；异常退出后可恢复自动草稿或保留原文件；删除进入回收区，可恢复 |

关卡列表中「已试通」表示**当前这一份布局**存在一次完整通关记录。它不是求解器认证，不表示关卡有唯一解或体验质量已被验收。

## 4. 格子与叠层：本作特有的编辑问题

底层数据有墙、目标和可动物体；它们并非一条随意排序的图层列表。编辑器将它们明确分区：

- **地形**：无墙/白墙/黑墙/灰墙，一格至多一面墙。
- **目标**：白/黑的箱子目标、玩家目标。目标不因视觉显示在上方就改变碰撞顺序。
- **物体堆叠**：白/黑箱子、白/黑玩家，从上到下列出；同时显示棋盘实际视图和被遮挡的物体缩略图。

点选格子后，右侧显示坐标、全部对象与“顶层/被覆盖”的说明。点击列表层选中那个对象；删除、换色、调序作用于所选物体，不能误删整格。墙和目标不参与可动物体的上移/下移。物体换色不偷偷删除另一对象；冲突作为待处理问题呈现。

两种不同语义的显示控制必须分开：

1. **黑/白视角预览**：仅改变编辑画面的显示方式，方便预判进入游戏后哪种颜色是实体；不执行游戏中的切换命令，不改变布局。
2. **查看遮挡内容**：展示被覆盖对象或临时分层预览，只用于编辑，不写入关卡。

摆放默认规则：空格直接放置；格内有不同对象时先显示叠放预览，点击追加到物体顶层。对同类同色对象连续刷过不重复追加；明确的“再叠一层”才创建重复对象。更换墙只替换地形，保留其他内容并立刻显示冲突；灰墙上的物体必须处理后才能试跑。拖动跨格一次形成一个编辑命令。

白玩家与黑玩家各一名：在另一格摆玩家时，预览中显示旧位置并提示“移动白/黑玩家”，确认后整体迁移，一次撤销恢复。新建的未完成草稿可以暂时缺玩家或目标，仍然允许保存草稿；试跑前才强制结构有效。

## 5. 工具、键鼠与防误操作

| 操作 | 提议交互 | 边界 |
|---|---|---|
| 画笔 B | 左键绘制，拖动连续画；指针跟随半透明预览 | 一次按下到松开记为一次撤销；经过 UI 不继续落笔 |
| 擦除 E | 擦除所选类别/颜色；有多层时在预览中标明将删哪一层 | 清空整格是单独的明确命令；不用右键默认删除全部 |
| 选择 V | 单击选格，拖框选区；Shift 加选 | 物体模式与整格模式标明，批量操作只影响指定范围 |
| 直线 L / 矩形 U | 按下起点，拖动预览，松开提交 | 矩形可选空心/实心；Esc 取消正在拖的操作 |
| 填充 F | 预览连通范围后确认 | 只匹配地形；不越过色墙界线、不覆盖物体堆叠 |
| 吸管 I | 从选中层取对象与颜色 | 取到的笔刷在左侧高亮，避免只取到遮挡后的顶层 |
| 选区操作 | 复制、剪切、粘贴、平移、旋转90°、镜像 | 粘贴先为悬浮预览；说明越界和玩家唯一性冲突；确认后一次撤销 |
| 视野 | 滚轮以指针为中心缩放；中键或空格+拖动平移；Home 适配棋盘 | 编辑模式空格不切换玩家；不抢占文本框快捷键 |
| 历史 | Ctrl+Z 撤销，Ctrl+Shift+Z / Ctrl+Y 重做 | 删除、尺寸、整次笔画均可撤销；改动后清空重做分支；列表显示操作摘要 |
| 文件/试跑 | Ctrl+S 保存，F5 试跑，Esc 返回或取消当前操作 | 编辑时 Esc 优先取消拖动/弹窗；离开才触发未保存保护 |

核心入口既有鼠标按钮也有快捷键。首版面向 Windows 键鼠；完整手柄编辑不列为本轮完成条件。试跑继续使用现有键位，不改玩家的移动/撤销习惯。

## 6. 保存、校验与试跑闭环

### 保存

内置 21 关只读，编辑前生成带独立 ID 的工作副本。自制关卡放在用户数据目录内，不写回 Unity Assets，也不写游戏安装目录。菜单显示友好名称而不是文件路径。底层保存采用临时文件写入成功后替换，并保留最近成功副本；写入失败时保留未保存标记及已有文件。

自动恢复按静止间隔和关键操作触发，独立于手动保存；它不能把无效草稿误标成可游玩关卡。导入先完整解析、检查格式/大小/重复 ID，再展示预览；绝不静默覆盖已有同名关卡。导出默认打包一个含名称、主题和布局的 JSON 文件，也可提供兼容原始布局格式的导出。

### 校验

**阻止试跑，但允许保存草稿**：尺寸或数组损坏、未知对象/颜色、不是恰好一白一黑玩家、没有任何目标、同格多个底墙、物体或目标在灰墙上、数据无法被同一规则引擎载入。

**提示人工复核**：被覆盖玩家、同色物体多层、看起来封死的箱子、孤立目标、物体与目标数量不对称。第一版不将传统推箱子的角落死锁规则套用成硬错误：本作有异色穿透和黑白切换，简单几何检测容易误判。

坐标系在编辑器、导出和错误定位之间统一；玩家界面使用左下原点，从 `(1,1)` 开始；数据仍为从零开始、y 向上的原格式。错误项记录稳定对象标识，以便修复后刷新，不停留在失效坐标。

### 试跑

按 F5：结束笔画 → 检查 → 复制当前草稿快照 → 圆形遮罩闭合 → 进入共享游戏视图。试跑中不修改文档；撤销和重置仅作用于试跑会话。Esc/返回编辑：闭合遮罩 → 丢弃试跑状态 → 恢复原画布缩放、平移、选格和编辑撤销栈。

**画布边框不是实体墙。** 当前规则允许角色和箱子进入序列化矩形之外的空白空间。尺寸调整只改变编辑/保存范围，不自动围墙，也不改变试跑的边界规则。画布外使用弱化网格并提示“范围外为空白”；LD 需要封闭空间时须明确绘制墙。裁切后产生的开口应在预览与检查建议中提示。

成功时显示「试跑通过」和返回编辑/重新试跑，不跳剧情选关。记录关卡布局哈希、规则版本、完整指令与结果；规则相关改动使“已试通”标记失效，重命名不必失效。保存或导入后再次回放可验证解法仍适用。

## 7. TD 模块拆分与现有工程衔接

| 模块 | 拥有的数据/职责 | 与现有实现关系 |
|---|---|---|
| LevelDocument | 版本、ID、名称、主题、布局；有效/无效草稿均可存在 | 保留现有 LevelData 作为布局载荷，用版本化包裹层承载作者元信息 |
| EditSession | 工具、笔刷、选格/选区、视口、原子命令与撤销重做 | 与 PuzzleSession 历史分离；不通过执行游戏命令修改编辑文档 |
| LevelValidation | 多条结构错误和定位信息、建议 | 与 PuzzleDefinition.FromData 共用规则约束；仍以核心载入为最后防线，避免两套判定漂移 |
| UserLevelLibrary | 列表、手动保存、自动恢复、备份、导入导出、回收 | 不复用剧情 ProgressStore 的完成集合；文件 IO 错误显式返回 UI |
| PlaytestController | 草稿快照、同一玩法会话、解法记录、结果回传 | 扩展 PuzzleApp 的自定义关卡返回路径；继续复用 Core、BoardView、音效与输入 |
| EditorView | 关卡库、画布、属性栏、对话框、快捷键焦点 | 固定 UI 使用场景对象/Prefab；地图是数据生成；编辑与试跑可在共享场景内切换根节点 |

不增加一关一个 Scene。也不为了编辑器复制一份推箱子引擎。原作两章运行内容仍放在现有模块内，编辑器代码可分 `Runtime/LevelEditor`、固定 UI 放 `Prefabs/LevelEditor`；研究与稿件继续在本目录管理。

## 8. 完整首版的验收边界

这是一组可验证的阶段，不用“轻量”减少编辑闭环。按顺序实现；只有前面做扎实再进入下一阶段。

1. **文档可靠**：新建无效草稿也能保存；所有编辑操作可撤销/重做；导入导出往返无丢层；中断写入保住旧存档；自动恢复与手动保存区分。
2. **单格与绘制可靠**：两章全部对象；黑白堆叠、玩家唯一性、墙与目标分区；连续画笔、擦除、选择、吸管、视野操作；1280×720 与 1920×1080 下主要控件无需横向滚动。
3. **完整制作工具**：直线、矩形、地形填充、选区复制/变换、尺寸锚定裁切；每项支持取消、预览、一次撤销。
4. **试跑闭环可靠**：同一 Core；编辑中试跑不要求先覆盖保存；返回精确恢复编辑状态；错误可定位；通关记录随布局变化正确失效；不污染剧情进度。
5. **玩家可用性验收**：从主菜单开始，不借助 Unity 或外部文件操作完成“新建→绘制→叠层→修错→试通→保存→退出重开→继续编辑→导出/导入”；观察误操作、找控件耗时和遮挡理解问题，再迭代。

自动化覆盖命令撤销/重做、坐标与裁切、导入导出、损坏恢复、试跑隔离；运行验收覆盖真实 UI 事件、分辨率、窗口焦点、重复打开/关闭。单元测试通过不能替代玩家操作和美术验收。

首版不做：联网工坊、多人协作、自动生成关卡、可解性搜索器、后续章节机制、通用可视化脚本。以上能力不能挤占基本编辑闭环的质量。
