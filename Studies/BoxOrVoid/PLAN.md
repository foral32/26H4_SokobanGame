# 前两章复刻实施计划

> 依据：[GOAL](GOAL.md)。质量先于体量；同一玩法场景读取 21 关数据。本计划随原作证据补充细节，不扩大章节范围，不提交 Git。

## 1. 规则、内容与表现取证（已完成本次范围）

- `Research/Rules.md`：记录对象堆叠、颜色/控制、推动、目标、撤销、重置的证据和未知项；反编译与视频对照。
- `Research/Levels.json`：21 关的来源、校验值、显示编号、顺序、尺寸、教学提示与目标。
- `Tools/inspect_reference_assets.py`、`Research/Extracted/`：读取本地参考包的资产/序列化参数；提取素材另记来源，不复制原作玩法程序集进入 Assets。
- `Research/Frames/`：按视频时间点留取前两章教学、切换、叠层、箱子、选关、过关的画面。
- 检查点：解释教程关键步骤和箱子交互；确认哪些状态藏在物体下方，哪些状态参与过关。不能仅从关卡文件名推断游戏内顺序。

## 2. 代表关卡的确定性规则与回放

- `Assets/Studies/BoxOrVoid/Core/`：纯 C# 的 `PuzzleDefinition`（格子/对象配置）、`PuzzleState`（分层对象状态/控制颜色）、`PuzzleSession`（操作、撤销、重置）。此程序集不依赖 UnityEngine。
- `Assets/Studies/BoxOrVoid/Tests/EditMode/`：先写基于取证的规则测试，再实现；覆盖异色支撑、同色阻挡、同色箱链、覆盖角色、叠层顺序、目标类型/颜色/覆盖、切换撤销、重置恢复。
- `Tools/RuleHarness/`：直接编译同一 Core 源码，便于快速执行规则测试和求解；不另写一套被当成产品的规则。
- 输入为四方向、切换、撤销、重置；每个有效操作返回可呈现的状态变化。表现插值不回写权威状态。
- 检查点：教程 01/03 和箱子 01/03/06 等实际教学行为（最终按取证选定）在同一逻辑内通过；至少一条叠层交互序列与视频逐步一致。

## 3. 共享场景的完整纵向体验

- `Runtime/PuzzleApp.cs` 编排标题/章节/选关/游戏/暂停/完成流程；`Runtime/PuzzleInput.cs` 负责按键与重复节奏；`Runtime/BoardView.cs` 只负责从状态渲染棋盘、角色、箱子、目标和叠层提示。
- `Runtime/PuzzleAudio.cs` 与表现配置承担音效、切换、完成反馈；`Runtime/ProgressStore.cs` 使用独立存档路径，处理不存在或损坏的存档，不接触原作存档。
- `Content/Levels/` 保存数据化关卡，`Art/` 与 `Audio/` 保存所需素材；共享场景 `Scenes/BoxOrVoid.unity` 不随关卡增多。
- `Editor/StudyBuilder.cs` 创建/检查本任务资产并以显式场景列表构建，不改动原 Gameplay 场景；轻量 `Editor/LevelWorkbench.cs` 提供选择、查看、修改数据及试跑。
- 检查点：实际运行代表关卡，对照原作画面和操作节奏，修正可读性、切换、遮挡提示、撤销与重试，再进入全量关卡。

## 4. 两章内容、进程和运行验证

- 补齐两章原始数据、游戏内名称/编号、教学提示、选关布局、解锁与进度恢复。
- `Content/Replays/`：全部 21 关有效操作序列；回放验证调用产品 Core。记录哪些来自视频，哪些由独立求解产生，并验证终局条件与原作语义。
- 自动化测试验证全部关卡可载入、回放通关、撤销/重置、保存恢复；Unity 中检查实际输入适配、界面流程、渲染和音效。
- 检查点：全部 21 关有证据；Windows 构建能够启动游玩；纯逻辑通过与实际输入/画面检查分别报告。

## 5. TD / LD / 玩家审查与交付

- `Research/LevelAnalysis.md` 逐关整理教学目的、关键发现、解法与难度衔接；不以布局列表替代分析。
- `Evidence/` 保存真实运行截图/录像、测试和构建记录，按日期保留问题→修正→复测。
- `README.md` 提供启动场景、构建、操作、目录说明、已知差异；`Review.md` 说明可迁移到后续项目的具体经验。
- 最终逐项核对 GOAL，不遗漏轻量数据编辑、独立存档、UI 完整流程及真实画面验证。用户验收与自主交付完成分别记录。
