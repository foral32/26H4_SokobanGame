# Box or Void · TD 拆解工作台

本地交互式研究界面，以技术策划视角把机制、关卡与实现连接起来。范围为「欢迎」8 关、「箱即是空」13 关。界面素材来自本项目的原作取证与复刻运行；没有用概念图代替实机。

## 打开

当前地址：<http://127.0.0.1:4177/>。

关闭后可双击本目录的 `打开拆解工作台.cmd`。启动器检查本地服务，必要时在后台启动静态版本，然后打开浏览器。需要本机已安装的 Node.js；正常阅读无需启动 Unity，也不需要联网获取字体、图片或音频。

## 建议阅读路径

1. 「程序结构 / 从运行开始」：逐步查看场景入口、Awake、Start、选关、每帧输入与反馈。节点会标出对象的创建时机，源码按需展开。
2. 「一步怎么计算」：选择连续推箱或链尾受阻，单步对照棋盘、调用栈、移动计划和变量。坐标在提交阶段才改变；这里展示的提交中间态只用于解释，Unity 对外返回完整结果。
3. 「状态与撤销」：移动、切换、重置，再撤销，观察当前 State、历史栈和重置检查点。「关键组件」可查看各组件的类型、输入、输出与数据归属。
4. 「墙块 mask」：点击 3×3 邻格，查看缺边位、二进制、编号与贴图。尝试内部缺角，分别开关角片；展开 16 种组合可反向生成邻接配置。
5. 「规则实验室」可自由操作；「关卡设计表」支持筛选、关键步回放、两关对照与 CSV 导出；「声音工作台」可试听真实资源并查看触发条件。
6. 收藏和笔记保存在当前浏览器的 localStorage，可导出 Markdown。

「动画与动效」新增 5 组、16 个效果：选择案例，慢放或逐帧，点击曲线定位源码。时间轴靠近预览，细小标记提供局部放大。参数实验可恢复工程值；圆形转场可显示网格、切换屏幕比例；实机录像单独播放。详见 [动效拆解.md](动效拆解.md)。

`Ctrl + K` 打开全局搜索。`Esc` 关闭弹窗。沙盘聚焦后支持方向键 / WASD、空格切换、Z 撤回、R 重置。

## 内容与证据边界

- **原作取证**：本地 Demo 的 JSON、资源映射、原作程序集取证与提供的实机录像。
- **TD / LD 分析**：教学作用、策划问题、误判与可迁移方法是基于布局和行为的分析，不冒充作者自述。
- **复刻实现**：纯状态分层、共享场景、网页相机计算器和代码查看器明确指向本项目实现，不代表原作采用相同代码结构。
- 网页是独立的离散规则解释器，并未连接 Unity 实时调试器；启动图和源码来自本工程的复刻实现。解释器的普通执行与单步执行共用计算路径，并与 21 关 Core 回放逐步对齐。朝向、物理输入与动画时序不以网页演示作为验收。
- 所有回放为有效解，未宣称最短；步数、切换次数不等同于经过玩家实验的难度评分。
- 已知原作音效空字段（如 goalUnfulfilled）明确留空，未虚构取消音效。音频为原 WAV 转码；音高变化和冷却在依据中解释，不把试听混音当作原作完整混音。
- 实机截图和短片来自此前归档的复刻版本；资料构建时读入当前研究文档与代码，可能包含后续迭代记录。

## 源码与重建

|文件|职责|
|---|---|
|`src/main.jsx`|各研究工作区、回放、搜索、对照、笔记与试听|
|`src/Board.jsx`|根据原始 Sprite 元数据投影棋盘，支持下层标记与格子检查|
|`src/engine.js`|共用的网页规则执行与可视化步骤记录|
|`src/ProgramExplorer.jsx` / `program-model.js`|启动、移动单步、历史快照和组件关系|
|`src/MaskExplorer.jsx` / `wall-tiles.js`|邻格、缺边编码、16 张贴图、独立角片；棋盘使用相同的编码函数|
|`src/SourceExcerpt.jsx`|从当前源码快照按标记定位，显示真实行号|
|`src/MotionExplorer.jsx` / `MotionPreview.jsx`|动效工作台、Sprite / 菜单 / 光圈 / 粒子预览|
|`src/motion-model.js` / `motion-content.js`|16 个动效的公式、真实局面与关键时刻|
|`scripts/motion_sources.py`|从当前 C# 与场景读取参数、记录源码散列|
|`src/content.js`|策划问题、关键状态、技术契约与分析文案|
|`scripts/prepare_data.py`|从本工程研究资料生成数据、预览图、声音波形与本地媒体|
|`scripts/server.mjs`|仅监听 127.0.0.1:4177 的静态服务，支持媒体 Range 请求|

本目录独立于 Unity `Assets`，未改动玩法、Unity 场景或项目设置。

重建：先 `npm ci`，再 `npm run prepare:data`、`npm run build`。数据准备依赖本机已保留的取证资料、Pillow 及脚本指定的 FFmpeg；Satoshi 字体首次缓存来自 Fontshare，之后使用本地缓存。

开发：`npm run dev`。静态运行：`npm start`。两者使用同一端口，不同时启动。
