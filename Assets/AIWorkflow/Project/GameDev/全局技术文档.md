## 框架使用约定

- **`ConoBehavior`**：新脚本优先继承此基类（而非 MonoBehaviour）。提供 `ManagedInitialize` / `ManagedDestroy` 生命周期钩子。
- **`Singleton<T>`**：仅用于全局管理器（World、GenericUIManager 等），不用于业务逻辑组件。
- **`GenericObjectPool`**：所有频繁生成/销毁的对象（子弹、特效粒子）必须走对象池。
- **`UEvent`**：跨模块通信优先使用事件，避免直接引用。
- **异步任务**：统一使用 UniTask，不混用 Coroutine 和 `Task.Delay`。

## 代码规范

### 结构组织
- 使用 `#region` + 中文标题整理脚本结构，按功能模块划分
- 优先继承 `ConoBehavior` 而非 `MonoBehaviour`，使用 `ManagedInitialize` / `ManagedDestroy` 生命周期

### 代码精简
- 尽量减少代码行数和函数冗余
- 避免过度封装，保持代码简洁直观

### 注释原则
- 对不易懂的逻辑保留必要注释
- 删除无意义的注释（如自解释的代码）
- 注释使用中文，简洁明了

### 命名规范
- 公共成员使用 PascalCase（`PlayerHealth`）
- 私有成员使用 camelCase（`playerHealth`）
- 常量使用 PascalCase（`MaxHealth`）
- 布尔变量使用 `b/Is/Has/Can` 前缀（`IsDead`、`CanJump`）
- 协程方法使用 `~` 后缀（`WaitForSeconds` → `WaitForSeconds~`）

### 异步与性能
- 异步任务统一使用 UniTask，不混用 Coroutine 和 `Task.Delay`
- 高频路径（Update、碰撞检测）必须零 GC 分配
- 避免在 Update 中每帧调用 `Physics.OverlapSphere`，改用事件触发或降频检测
## 渲染与视觉目标

- 渲染管线：URP + MK Toon（卡通风格）
- 目标帧率：PC 60fps
- 后处理：PostProcessManager（Vignette、Bloom、色彩调整，由 DOTween 驱动过渡）

## 性能约束

- GC 分配：高频路径（Update、碰撞检测）必须零分配
- 对象池覆盖：特效粒子、投射物、音效实例
- Physics：避免在 Update 中每帧调用 `Physics.OverlapSphere`，改用事件触发或降频检测
