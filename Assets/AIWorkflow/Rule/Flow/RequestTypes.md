# 需求类型定义

## 简单任务
- 目的：快速完成的小改动、小功能、小修复
- 特点：影响范围小、依赖少、无需单独架构判断
- 执行路径：Planner快速澄清 -> Programmer实现 -> 快速检查 -> 交付

## 普通任务
- 目的：需要轻量规划的功能开发或改进
- 特点：可能涉及多个文件或简单协作，但不一定需要架构介入
- 执行路径：Planner拆解 -> 必要时Architect补充边界 -> Programmer实现 -> 快速检查 -> 交付

## 复杂任务
- 目的：跨模块、公共框架或复用层改动
- 特点：需要先明确边界与风险，再拆成小步执行
- 执行路径：Planner拆小任务 -> Architect确认关键方案 -> Programmer分步实现 -> 每步快速检查 -> 交付

## 路由规则
- 默认按最短路径执行，不为小任务引入额外流程
- 仅当涉及跨模块、公共框架、复用性设计时才进入ArchitectureReview
- 仅在任务被阻塞、目标变化或发现重大风险时触发重新规划

## 需求模板（最小字段）
- 标题
- 目标
- 需求描述
- 约束条件
- 完成标准
- 影响范围（文件/模块）
