# 工作流规划循环规则

## 轻量规划循环（Clarify -> Do -> Check）

### 阶段1：快速澄清（Clarify）
执行前只收集当前任务真正需要的事实：
- 目标是什么
- 影响哪些文件或模块
- 是否存在明显依赖或阻塞
- 是否需要 `Architect` 介入

#### Planner的快速检查清单
`
- [ ] 目标与完成标准明确
- [ ] 影响范围已识别
- [ ] 是否需要架构介入已判断
- [ ] 下一步执行者明确
`

#### Architect的快速检查清单（按需）
`
- [ ] 关键模块边界明确
- [ ] 复用或基础层风险明确
- [ ] 已给出足够短的实现约束
`

#### Programmer的快速检查清单
`
- [ ] 任务说明已理解
- [ ] 受影响位置已确认
- [ ] 快速自检方式已明确
`

### 阶段2：执行（Do）
按照当前最短路径推进：
- 完成任务
- 更新当前状态
- 发现阻塞立即回传

### 阶段3：快速检查（Check）
只检查是否满足交付的最低要求：
- 内容是否自洽
- 关键路径是否可执行
- 是否有需要记录的限制或风险

## 中止与恢复
- 任务阻塞时保存当前状态到任务记录
- 恢复时从最近状态继续，无需重跑完整流程

## 何时触发重新规划
1. 新任务到来且目标不清晰
2. 任务范围发生变化
3. 出现明显阻塞或高风险
4. 实现发现需要 `Architect` 重新介入
