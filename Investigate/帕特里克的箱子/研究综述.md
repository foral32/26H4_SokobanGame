## 2. 核心机制不是一句题材口号

**已核验事实**：箱子拥有内部空间，空间可继续包含箱子；存在箱子包含自己的递归结构。作者说明入口采用侧边中心，放弃了早期沿整条边寻找空位的方式，因为那种行为难以记忆、推理，容易形成别扭的谜题。[S1]

**官方规则接口**：通常按 push → enter → eat → possess 的顺序尝试操作；Priority 区域更改顺序。官方文件以 Block 表达内部空间，以 Ref 引用已有空间。[S2]

**分析**：最值得学习的变化是：同一个对象既是外层棋盘上占一格的障碍，也是能改变人物位置关系的内部棋盘。一个方向输入的含义取决于局面，而非新增一排技能按钮。

### 局部推理例：墙为什么变成工具

这是一段根据规则构造的解释，不是对某一正式关卡的复现：

1. 玩家从左侧接触可进入的容器；右侧空着时，优先推动，容器向右移动。
2. 容器被右侧墙挡住后，外部推动不能成功。
3. 若左侧中心入口满足进入条件，同一向右输入可以进入容器内部。
4. 因此玩家会从“把箱子推走”转向“先把箱子推到合适的阻挡物旁，再进入它”。

墙由单纯障碍兼任固定容器的工具。关卡可以通过墙的位置、入口朝向、内部通路和目标位置来组织推理，无须每关新增物件。这是我对已核验规则的设计分析。

## 3. 核心规则、附加规则与关卡推论

- **核心层**：物体拥有空间，推动与进入产生内外位置变换。
- **自然延伸**：在内部搬运其他箱子，以及嵌套和自包含；玩家需要推理空间关系。
- **显式规则变体**：官方资料出现动作优先级、可附身属性、多玩家移动顺序、翻转及无限进入/退出等配置。配置证明变体存在，不足以代替完整交互试玩；未核验的细节不写成确定操作攻略。[S2]
- **布局层**：墙、狭窄通道、目标位置、箱子初始相对位置可以改变同一规则的用途。它们不是另一套独立技能。

## 4. 关卡怎样长出来

作者自己的设计方法包括围绕必要交互构关、考察机制组合、在试验场探索，以及为玩家的误解制作澄清关卡。他也展示了从同一想法发展出的四个关卡变体。[S3]

本次查看并保存了原文的两张图：

- `来源/parabox_transfer_set.webp`：四幅图的箱子数量、相对排列及边界形状不同；作者明确将它们归为同一思路的变体。不能仅凭静态图认定完整解法或发布顺序。
- `来源/parabox_rescue_sequence.webp`：作者说明这是继续探索“从墙边救回箱子”产生的关卡。说明一个交互可以被继续挖掘，而不是用完即换主题。[S3]

### 如何从交互生成可评价的关卡（本研究的归纳）

先写出玩家本关要学会的一句话，再设计局面，并检查：

1. 目标：玩家必须改变哪个状态？
2. 困境：最直接的办法为何不可行？
3. 洞察：哪条既有规则能改变这个困境？
4. 必要性：玩家能否绕开洞察直接过关？若能，这是教学允许的偶然成功，还是破坏关卡目的的捷径？
5. 精简：去掉哪块墙、箱子或空地会失去这条推理？保留必要的实验余地，不把“紧凑”误解为格格卡死。
6. 后续：下一关如何区分“真的理解”和“刚才恰好试出来”？

## 5. 关卡编排：管理玩家已有的知识

作者在访谈中说，先制作试验关发现交互，再制作呈现这些交互的谜题；试玩中如果某概念掌握不足，会补充关卡，并反复调整顺序。[S4] 另一篇访谈说明，作者接受某关偶然通关，但会让紧接着的关卡再次要求玩家处理该概念。[S1]

下面是归纳出的教学链，不是原作逐关清单：

| 环节 | 设计任务 | 玩家获得的认识 |
|---|---|---|
| 初次发现 | 缩小无关选择，让关键交互容易发生 | 知道规则存在 |
| 主动复用 | 改变位置或入口条件，仍要求同一交互 | 能预测规则何时适用 |
| 边界澄清 | 让直觉上的类似操作失败且原因可见 | 知道规则的适用条件 |
| 旧知组合 | 必须先处理已学规则，才用得上新规则 | 能推理操作顺序 |
| 认识反转 | 把原来的障碍变成解法条件 | 发现规则的新用途 |
| 综合应用 | 混合已掌握概念，增加规划跨度 | 独立运用完整知识链 |

这条链的难度不等同于棋盘尺寸或解法步数。判断卡点时应区分规则不懂、状态看不清、计划过长、误操作和错误反馈不足。

## 6. 产品体验与编辑器如何服务机制

作者的视觉访谈谈到不断调整颜色、线宽、轮廓和挤压动画；这说明简约外观本身也需要持续打磨。[S4] 本研究的判断是：对于多层空间，视觉必须帮助玩家追踪“哪个对象移动了、进入哪里、为何受阻”，动效不能模糊离散状态。

官方编辑支持采用精简 Unity 工程，保存时导出关卡文本，再在游戏内加载并快速刷新；也提供镜像、调整大小、内外层移动及设置引用等工具。这是作者控制开发成本的选择，不是完整游戏内编辑器。[S2]

对本次笔试的建议：编辑器需求应能对应实际设计工作，例如复制局面、修改少量格子、马上试玩、保留编辑初态、保存与重载一致。若最终机制涉及嵌套或引用，再考虑对应可视化。不能把原作工具方案直接认定为满足本题，题目没有明确编辑器必须是哪一种形态。

## 7. 对下一轮创意的约束（分析建议，未立项）

先做一个能产生多种局面的规则试验场，至少找到若干不同用途，而不是先列关卡数量。每个创意需要同时提供核心状态变化、关键条件、两项可推导后果、一个附加机制的组合价值，以及一条教学链。若只能提出主题和新按钮，尚未证明适合制作成推箱子系统。

一周范围内应同时估算规则实现、撤销/重置、教学关卡、完整流程、编辑与试玩往返的成本。不能只按主机制代码量判断可行性。
