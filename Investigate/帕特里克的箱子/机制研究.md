# 《帕特里克的箱子》机制研究

核验日期：2026-11-06。目的：研究成熟推箱子案例，为一周笔试（推箱子、完整关卡流程、关卡编辑器；Unity 6、纯 2D、简约美术）建立判断依据。本篇不提出新游戏创意，也不等同于复刻方案。

## 证据边界

本次读取官网、官方关卡格式文档、开发者本人文章及采访中的回答。没有亲自运行游戏或逐帧检查官方宣传片。下文把**官方确认**、**基于规则的设计分析**、**尚待直接核验**分开；章节名称存在，不代表已经核验该章全部规则。

## 1. 核心不是“箱子会变小”，而是箱子兼有物体与空间两种身份

**官方确认：**箱子内部可以包含区域、其他箱子及其内部区域；玩家可以把箱子推进、推出其他箱子。箱子还可以包含自己。开发者特别举过“把包含自身的箱子再推入另一个箱子”的例子：变化的是世界结构。[官网](https://www.patricksparabox.com/)；[开发者 2023 年访谈，递归例子](https://www.gamedeveloper.com/design/patrick-s-parabox-)

**设计分析：**普通推箱子主要改变物体在一张棋盘上的位置；本作还改变“哪个空间位于哪个空间之内”。因此，一个箱子可以同时是占格障碍、可移动容器及通向内部地图的入口。缩放动画解释这种关系，空间关系才是规则本身。

可核验的最小概念链为：

1. A 在外层占据一个格子，并有自己的内部棋盘。
2. B 被移入 A 后，B 的位置属于 A 的内部棋盘。
3. A 自包含时，看到的“小 A”是同一空间的再次出现，不能简单理解为另一份互不相关的地图。

前两步来自官方的容器描述；第三步是对开发者“包含自身”表述的结构化解释，不是对其运行时代码的断言。

## 2. 普通推动、进入和退出：先看动作优先级，再看入口

**官方确认：**开发者访谈讨论了成排推箱，以及从某一侧进入时使用该侧中心位置的规则。作者曾试过中心受阻后依次寻找该边其他空格，后来删掉了这种行为，保留中心入口，以降低规则的任意性。[开发者 2023 年访谈，规则迭代段](https://www.gamedeveloper.com/design/patrick-s-parabox-)

**官方确认：**标准尝试顺序为 `push → enter → eat → possess`；Priority 区域改成 `enter → eat → push → possess`。这说明改变优先级属于局部变体。[官方自定义关卡文档，Header](https://www.patricksparabox.com/custom-levels/)

**设计分析：**理解容器时，不能只问“它有洞吗”，还要问“前面的推动能否成功”。容器前方有空位时，玩家通常先推动容器；容器被墙固定、无法平移，且入口条件成立时，进入才成为可用结果。于是墙同时具有两种作用：限制移动，以及固定容器以便进入。后者来自既有规则的组合，并不需要新增一种特殊墙。

这里的靠墙例子是对已确认规则的最小演绎，不声称对应某个已亲测的关卡编号。它也不是“靠墙必定能进”：入口或内部阻挡仍可能令进入失败。

**退出的证据范围：**官网明确存在将物体推出容器的行为。开发者访谈指出，进入后保留外部环境的视觉上下文，可以帮助玩家看出外侧墙为何阻止某方向退出。本次未核验不同尺寸、偶数边长、相邻容器间连续转移时的全部坐标映射，不能把“中心进入”扩大为“所有出入都只能发生在中心”。[官网](https://www.patricksparabox.com/)；[开发者 2023 年访谈，视觉上下文段](https://www.gamedeveloper.com/design/patrick-s-parabox-)

## 3. 递归为什么能持续产生题目

**官方确认：**开发历史先有箱中箱，后来加入跨层进出，再受到 Sokosoko 启发加入自包含。开发者还提出过“一个箱子含自身的两个副本，退出时怎么办”的具体边界问题，说明规则选择需要同时考虑谜题、程序与视觉的一致性。[开发者 2020 年访谈](https://www.gamedeveloper.com/business/road-to-the-igf-patrick-traynor-s-i-patrick-s-parabox-i-)

**设计分析：**这揭示了三层研究对象，不能混为“不断增加道具”：

| 层次 | 变化的是什么 | 本作的研究例子 |
|---|---|---|
| 基础操作 | 物体能做哪些动作 | 推动、进入、退出 |
| 结构组合 | 既有对象如何连接 | 层层嵌套、自包含、同一空间有多个外部表示 |
| 边界裁定 | 多个结果都似乎成立时如何选 | 推动与进入谁优先；多个引用时从哪里退出 |

递归带来的不是单纯更深的地图，而是玩家必须重新判断当前所在空间及它与外部对象的关系。即使外观仍是少量方块，状态推理也会显著增加。

## 4. 附加机制：哪些已经确认，哪些仍不能下完整定义

以下只记录一手材料能够承担的结论。

| 机制族 | 已核验的事实 | 分析与边界 |
|---|---|---|
| Eat | 官方动作优先级含此动作 | 可确认它是规则的一部分；本次未直接验证吞入触发与跨层冲突，不把社区的简写当作完整规格 |
| 引用与出口 | 格式允许 `Ref` 指向已定义的箱子，并有 `exitblock` | 可分析“空间身份”与“外部表示”分离；不能直接把 Clone 解释为生成独立副本 |
| 玩家、占据、墙 | 对象格式包含 `player`、`possessable`；墙也支持这些字段 | 支持研究对象与控制身份组合；占据的精确切换条件未亲测 |
| Flip | 格式有 `fliph` | 可确认翻转属性；复杂进出方向的映射尚未逐案验证 |
| 无限进出 | 格式有 `infenter`、`infexit` 及其阶数 | 可确认这些状态被明确建模；触发、可逆性与特殊关卡用途未直接验证 |
| 附录 | 文档有 Priority 的不同顺序及 `inner_push` 等开关 | 附录会改变规则，不应反推普通章节也具备这些行为 |

表中存在性依据：[官方自定义关卡文档，Header 与 Objects](https://www.patricksparabox.com/custom-levels/)。它是作者公开的数据格式，不是完整运行时动作算法；本表有意不将字段存在扩写成未经观察的规则。

**一个可复核的官方实例：**文档示例中，同一根空间拥有两个指回自身的引用，出口标记不同。这个实例直接证明“同一空间可以有多个表示”和“出口需要明确区分”，但不足以单独证明每个 Clone 谜题的完整行动过程。[官方示例关卡](https://www.patricksparabox.com/custom-levels/)

## 5. 从案例中可以成立的设计判断

**事实：**作者选择机制时重视自然、易推理、能支持许多关卡；他会先做测试布局，发现交互，再围绕交互做谜题。简约视觉也经过颜色、线宽、轮廓、动画等大量迭代。[开发者 2023 年 PSU 访谈](https://www.psu.com/news/interview-with-patricks-parabox-developer-patrick-traynor-ps5-ps4/)

**分析：**本作的价值在于少量规则之间能形成新的用途。比如墙固定容器的用途，是推动优先与容器可进入共同产生的；自包含则让普通进出发生在循环空间关系中。新增章节不必等于新增独立按键、道具或 UI。

**事实：**作者自己的关卡设计文章给出了本作“救出贴墙箱子”的探索实例，以及四个围绕同一想法变化的谜题。文章的证据足以证明同一交互可以发展出多个变体，但单靠配图不能推出每一关的完整解法。[作者《Puzzle Level Idea Strategies》](https://cwpat.me/misc/puzzle-level-idea-strategies/)

**对本次笔试的判断：**纯 2D 与简约美术能够承载深规则，但不能据此认为实现成本低。作者明确说核心逻辑和渲染曾多次重写，递归边界很多；平滑跨层动画也很复杂。这个成熟案例证明的是规则深度与呈现清晰度的价值，不证明一周能完成同等递归系统。[开发者 2020 年访谈](https://www.gamedeveloper.com/business/road-to-the-igf-patrick-traynor-s-i-patrick-s-parabox-i-)

另需区分作业交付要求与案例做法：本作公开的编辑工具是随游戏提供的精简 Unity 工程，而非完整游戏内编辑器。这个事实不自动满足笔试所要求的编辑器形式。[官方编辑文档](https://www.patricksparabox.com/custom-levels/)

## 6. 后续复核点

1. 直接运行当前版本，检查 Eat 的最小触发场景、成功后各对象位置，以及多个动作候选的跨层处理。
2. 分别观察 Reference/Clone 的共享内容与退出位置，避免把“引用”“复制”“传送”混成一个概念。
3. 检查 Transfer 中的非中心连续转移与偶数宽度坐标映射；不要用普通中心入口规则代替全部边界规则。
4. 分别记录无限退出与无限进入的触发、符号、目的空间与撤销行为，不混用两种情况。
5. 若要写实现规格，再读取游戏所附编辑工程与实测；当前材料适合案例研究，不足以作为完整兼容性规范。
